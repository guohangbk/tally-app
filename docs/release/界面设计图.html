Tally.

塔莉

小莉帮你管好每一笔收支。

Tally 塔莉是一台只存在手机里的记账本：记账、看统计、整理分类、导入导出、备份恢复都不依赖网络， 也没有账号。小莉（AI）是可选增强——不开它，语音速记与截图记账照样在手机里跑完； 开了它，机器也只负责把草稿摆好，落库这一步永远留给人。 这块板收录该版本的全部界面：设计语言、图标系统、导航与组件规格，以及三十一节的逐屏样子。

设计取向

  • 纸墨为底，金晕只给小莉：AI 的存在感靠"什么时候出现"表达
  • 金额用衬线等宽字，整数与小数分两段排，扫一眼就能比大小
  • 每一屏最多一条灰字说明，说人话，不写操作手册
  • 选中态不只靠颜色：加勾、加描边或左侧色条
  • 触摸目标 ≥ 48dp，视觉上可以只是一个小图标
  • 提示一律贴底自动收起；破坏性动作先确认、事后可撤销

本期不做

  • 账户与资产管理、账户间转账（没有账户，转账就没有意义）
  • 预算、标签、优惠券与手续费明细、多币种
  • 云同步与图片云端存储：只有本机加密备份与手动 WebDAV 快照
  • 回收站：删除是软删 + 8 秒撤销，不做长期暂存
  • 自动入账：任何机器产出的草稿都不跳过人工确认
  • 桌面小组件、无障碍与通知监听记账
01

设计语言 · Design Language

一本纸账本，一朵茉莉
Ink & Jasmine

「塔莉」的名字里有「莉」。整套视觉以茉莉为母题：日常记账是安静克制的纸墨——骨白纸面、墨绿正文、 衬线数字；当 AI 介入时，画面里才会出现金晕（champagne glow）与五瓣花形。 智能不是靠渐变堆出来的，而是靠"什么时候出现"来表达：不开小莉，界面里没有一丝金色； 开了小莉，金色只出现在建议、光晕与生成中的动效上。这样 AI 的存在感天然可辨，也不会污染不用它时的克制。

导航 · 组件 · 动效

两个根页面 · 标记体系 · 选择态 · 双保存动词

账本与首次引导

账本只是数据分组
手势只教藏起来的那层

账本不是「账户」：没有资产账户这一层，账本只是数据分组——决定一笔记在哪里、算进哪组统计。分类是全机共用的一套字典，不随账本切换；这句话必须在引导里对用户讲明白，否则用户会拿它当钱包，把结余读成余额。 装完第一次看到的引导只到「数据在哪」这一层；真正要教的只剩一件藏起来的事——＋ 的长按扇形。它不占首屏，也不该在导入刚结束时抢注意力：第二次回到首页才浮一句，且只浮一次。一句讲不完的（长按账单批量选、账本名与菜单、小莉开关）收在气泡右侧的「更多手势」里，点开是半屏四行，不在首页再铺第二层字。

10.1

账本概览页

入口：账本列表点卡片进
概览卡 + 快速问答 + 分类占比 + 最近几笔

现在点进账本只是列表。改成点卡片进「概览页」：顶部是一本账的白底 TallyCard——IconTile + 账本名 + 笔数标签、大号总支出、一行时间跨度与日均；下面是快速问答、分类占比、最近几笔。 概览页不替代统计页——统计是任意区间的查询工具，概览是这本账的固定答案。看统计在顶栏右侧（与首页一致）。

10.2

项目结算 / 收尾

入口：账本卡动作行 / 概览页底部「结算」
确认弹窗 → 结算结果 sheet → 锁定账本

装修结束了，你想知道「装修到底花了多少钱、比预算多了多少」。结算 = 这本账的一次性汇总：总支出、时间范围、预算对比、分类占比、导出长图。 确认后账本被锁定，标记为「已结算」，之后不能往里记新账；要接着记，在账本列表的「已结算」区点「恢复记账」。没有单独的「归档」动作——结算就是锁定。

10.3

快速问答

入口：概览卡下方「快速问答」chips
四问：收入和结余 / 最大一笔 / 每月平均 / 某分类

有 5,739 笔账，你真正会问的问题不是「这个月花了多少」（首页已经有了），而是：「今年装修一共花了多少」「买车到现在已经花了多少」「上个月支出最多的一笔是什么」。 现在这些要经过搜索页 → 筛选条件 → 点统计才能看到。快速问答让「账本 + 时间范围」变成一个快捷入口，点一下出结果。四枚 chips 就地换结果：以下三屏是其中三种状态（「每月平均」的结构与「最大一笔」相同，单值 + 两格说明），顶栏一致。

判定与边界

  • 不新增计算口径：概览只发一条只读瘦查询（不取附件数、已退合计、账本与分期 JOIN，也不排序），聚合复用统计页同一套函数——页面省的是搬运，不是口径。
  • 快速问答不走 AI：模板走纯查询（已有统计口径），AI 没配也能用。与小莉那条线完全分开——小莉是对话式记账，问答是预设查询。
  • 结算长图复用海报管线：月度/年度海报那套渲染（PosterScreen / PosterViewModel）直接拿来画「这本账的总账」。抬头写账本名 + 完整日期跨度，不出环比与趋势。
  • 结算即锁定，没有单独的归档动作：确认结算后账本标记为「已结算」，列表里单独一区、可「恢复记账」；要彻底删掉仍走回收站。
  • 默认账本不允许结算：默认账本是持续使用的，没有「结束」的概念。列表动作行里的「结算」对它置灰，概览页底部不显示结算按钮；默认身份挂账本名旁的标签，切换默认在编辑弹窗里做。
  • 两个入口，一个结果：账本卡动作行点「结算」直接落在概览页并弹出确认框；概览页底部的「结算」按钮弹同一个确认框。
  • 结算结果 sheet 只有一个主动作：确认结算后就地弹出结果 sheet，「生成结算长图」是唯一按钮。
