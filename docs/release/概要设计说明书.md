## 1. 系统定位与边界

Tally 塔莉是一个**单机 Android 记账应用**：数据全部落在设备本地 SQLite，无账号、无服务端、无自动同步。AI（小莉）是可选增强，关闭后所有核心功能照常工作。

| 在系统内 | 在系统外 |
|---|---|
| 账本、账单、分类、图片、周期/分期、预算、提醒、回收站、导入导出、备份、桌面组件、长图分享、AI 调用与对话 | 银行账户对接、支付平台数据抓取、云同步服务、多端合并、消息推送 |

外部依赖只有三类：用户主动选择的文件（导入 / 备份）、用户配置的 AI 服务商 HTTPS 接口、用户手动使用的 WebDAV。

## 2. 设计约束与取舍

| 约束 | 来源与影响 |
|---|---|
| 金额用「分」的 `Long` | 精度不可妥协；界面格式化只在展示层做 |
| 机器产出一律先成草稿 | 语音、截图、AI 都不能直接写库，必须人点确认 |
| 无账号、无服务端 | 不做任何合并逻辑，同步字段只写不读 |
| 单机自用 | 不走迁移路径：`version` 一直是 1，改实体就直接改声明，手上设备的库按备份包重建；缺校验时报错停住而不是清库 |
| 构建基线互相咬死 | AGP 9.4.1 / Gradle 9.6.0 / Kotlin 2.3.21 / KSP 2.3.12 / compileSdk 37+minor 0 / minSdk 28，不能单独升降 |
| 不写自动化测试 | 交付靠 debug APK + 真机走查，因此界面与数据口径必须可被肉眼验证 |
| 边界由用户定死 | 不做账号、不做账户与资产、不做云同步。任何看起来「需要余额概念」的需求都被挡在门外（存钱计划、借还、转账）；口径表里不出现「账户」二字 |
| 权限增量只有一项 | `POST_NOTIFICATIONS`。无障碍、通知监听、存储、精确定位、生物识别一律不申请 |
| 不新增依赖 | 桌面组件走平台 `RemoteViews`，不引 Glance；其余全部复用已锁版本。真要新增坐标，必须单独验证能与 AGP 9.4.1 / Compose BOM 2026.09.00 线共存，解析不通就换方案而不是升基线 |
| 系统能力一律「有兜底」 | 通知可能被 ROM 杀、组件可能没空间放、快捷方式可能被 launcher 限流。每一项都要有一条不依赖系统的答案（见 §6） |
| 新页面不许另起视觉 | 全部复用《界面与交互规范》的组件与换算（1px≈1dp、px×1.2=sp），提示仍走 `TallyToast`，每屏 ≤ 1 条灰字 |

## 3. 总体架构

单 Gradle 模块 `:tally-app`，包内按职责分层：

```text
ui/            Compose 界面 + ViewModel + 导航        ← 只认 state，不碰 DAO
   ↓
di/AppGraph    手写依赖图（无 DI 框架），进程内单例
   ↓
domain/        模型、解析规则、排期算法、口径与状态机（纯 Kotlin，可脱离 Android 测试）
   ↓
data/          Room 仓储、DataStore、文件与图片、OCR/语音、AI 客户端、备份、导入导出、通知、长图
```

| 层 | 职责 | 关键类 |
|---|---|---|
| ui | 展示与事件；页面级 `StateFlow` | `TallyNavigation`、`TallyShell`、各 `*Screen.kt` / `*ViewModel.kt` |
| di | 组装依赖、暴露 `AppGraph` | `di/AppGraph.kt` |
| domain | 业务规则与算法，不依赖 Android | `domain/parser/*`、`domain/schedule/*`、`domain/ai/*`、`domain/model/*`、`domain/Period.kt` |
| data | 持久化与外部 IO | `data/repository/*`、`data/db/*`、`data/ai/*`、`data/backup/*`、`data/notify/*`、`data/share/*`、`data/preferences/*` |

规则：Compose 不直接访问 DAO；ViewModel 直接调 Repository（不引入 usecase 层）；DAO 保持单表；跨表事务在 Repository。

## 4. 模块划分

| 模块 | 范围 | 概要设计要点 |
|---|---|---|
| 主数据 | 账本、分类、图标 | 分类是全机字典，账本只是账单容器；两级为限；软删与归档分离 |
| 记账与统计 | 记账页、首页、搜索、统计 | 单一记账表单（新增/编辑/再记共用）；统计四段共用一次查询；口径唯一 |
| 数据进出 | 导入、导出、备份 | 导入可回滚批次；导出可原样读回；备份是加密容器不是数据文件 |
| 自动化 | 周期、分期、报销 | 排期算法在 domain，WorkManager 只做触发；幂等键唯一索引兜底 |
| 设置与个性化 | 偏好、主题、引导、提醒设置 | 偏好分两处：DataStore（设备本地）与 `app_setting`（随备份迁移） |
| 小莉与智能记账 | AI 配置、对话、语音、截图、关键词规则 | 网关是唯一入口；记账卡以消息形态落库；端侧规则永远先跑 |
| 提醒 | 四类通知、渠道、幂等游标、授权引导、点达深链 | 全部挂在既有每日 Worker 上，不新增 Worker，也不建提醒记录表 |
| 找回 | 回收站、保留期、彻底删除、附件物理回收 | 不加表，用 `deleted_at`；找回是查询与状态位问题，不是新数据 |
| 计划 | 预算模型、进度、阈值提醒、与月起止日对齐 | 进度数据与统计页同源（净支出），不另算一套 |
| 桌面 | **八枚只读组件**、两条快捷方式、长图分享 | 组件里不做写库，写库只发生在 App 内 |
| 设计系统 | 色板、字体、组件、图标、震动 | 全站复用同一批组件；金晕只给小莉 |

## 5. 数据架构

- 15 张表、单库、WAL；完整字段与索引见数据库设计文档。
- 版本 1、**没有迁移路径**（`TallyDatabase` 不挂 `addMigrations`，`version` 一直是 1），**也不配** `fallbackToDestructiveMigration`：改实体直接改 `data/db/entity/` 的声明，手上那台设备的库按备份包重建。Room 每次打开都会比对编译期的 identity hash 与库里 `room_master_table`，对不上就抛 `IllegalStateException` 停在可恢复提示——崩了数据还在能修，清了就没有了。
- 删表与改列走「建新表 → `INSERT SELECT` → 删旧 → 改名」，不依赖 `ALTER TABLE … RENAME COLUMN`（minSdk 28 的 SQLite 不保证支持）。
- 图片二进制在 `files/attachments/`，库里只有相对路径 + SHA-256 + 尺寸；按哈希去重；**一笔一张凭证**；物理回收按 `sha256` 引用计数，零引用且超保留期才删。
- 敏感值（API Key、WebDAV 口令）走 Android Keystore（AES/GCM），数据库只存引用名；两者都不进备份包。
- 预算与统计共用同一份净支出口径，退款按原单分类冲抵。

## 6. 关键技术方案

| 主题 | 方案 | 理由 |
|---|---|---|
| 状态管理 | 每页一个 ViewModel + `StateFlow`，一次性事件用可空字段（`notice` / `error`）交给贴底气泡 | 避免事件流与状态流两套机制 |
| 依赖注入 | 手写 `AppGraph` | 单模块规模下比 Hilt 少一层魔法，构造顺序可读 |
| 导航 | Navigation Compose 单图，路由常量集中在 `TallyNavigation` | 页面 33 个路由常量，够用 |
| 并发 | Room 事务单线程、查询 4 线程；AI/IO 走 `Dispatchers.IO` | 记账写入量小，读密集 |
| 后台任务 | WorkManager 每日一次 + 前台补执行；周期、分期、通知、清理共用一个 `AutomationWorker` | 省电且能补算错过的周期；不拆三个 Worker |
| 文本解析 | 端侧规则（日期→时间→金额→关键词→备注）为基线，AI 只做增强 | 断网可用、可解释 |
| OCR | ML Kit 端侧文字识别 | 图片不出设备，除非用户主动选云端 |
| 语音 | 系统 `SpeechRecognizer`，失败回退系统语音输入，再不可用则打字 | 自建 sherpa-onnx 栈体积不划算，已摘除 |
| AI 协议 | OpenAI 兼容 `chat/completions`，工具调用三级降级（tools → response_format → 文本围栏） | 服务商可换、网关差异可容忍 |
| 备份 | ZIP + `manifest.json` 明文 + AES-256-GCM 数据体 + PBKDF2 120k | 单文件可分享、可校验 |
| 主题 | 同一套 token 换值（`isDark`），不改布局 | 深色只做换色 |
| 每日未记账提醒 | `AutomationWorker` 每日在用户设定时刻跑一次：查当日是否存在 `deleted_at IS NULL` 的账单；无则发一条。已发标记写 DataStore（日期值），同日不重发 | 不建「提醒记录表」——一个日期标记就够，多一张表就多一处迁移 |
| 到期与失败通知 | 复用 `AutomationWorker` 的补执行结果：`catchUp` 返回的成功/跳过/失败计数交给 `TallyNotifier`；幂等靠两张自动化表的 `last_reminded_at` | 把通知接在既有执行点，而不是再排一个定时器去猜 |
| ROM 杀后台 | 所有提醒类通知都有「进 App 补算」路径：进前台时比对上次判定日期，错过时刻当天补发或静默补齐；界面上不承诺准点，只承诺「今天之内」 | 省电策略不可控；把承诺降到能兑现的档位，比加白名单引导更诚实 |
| 通知不外泄金额 | 通知正文只写「今天还没记账」不带金额；`setPublicVersion` 给锁屏用的脱敏文本 | 金额泄露有三条路，三条都要堵 |
| 区间统计 | `StatsGranularity` 加 `RANGE`，边界由 `domain/Period.kt` 算，四段仍共用一次查询快照 | 「四段一次查询」是性能与一致性的根，新增维度不能破坏它 |
| 预算 | `budget` 表 + 应用层按区间归堆比较；进度数据与统计页同源（净支出），不另算一套 | 预算和统计对不上是这类 App 最常见的信任崩塌点 |
| 退款冲抵 | 退款行仍是 `type=EXPENSE` + `refund_of_bill_id`；聚合时在退款自己的周期里从原单分类的支出中扣减，未关联原单的退款是中性行；累计额校验不得超原单 | 既不让退货虚增支出/收入，也不引入「账户余额」概念 |
| 回收站 | 不加表，用 `deleted_at`；保留期在 `app_setting`；清理任务与附件回收同一个 Worker | 找回是查询与状态位问题，不是新数据 |
| 桌面组件 | 平台 `RemoteViews`（`AppWidgetProvider` + `res/layout/widget_*.xml`），**八枚**组件只读本地数据；点击把 `NotificationLink` 递进 MainActivity，由 App 内完成跳转与写入 | 组件里做写库会把记账表单抄一遍。RemoteViews 的布局与颜色走独立的 `values/colors.xml`，不能读 Compose token |
| 组件刷新时机 | 四条：① 组件 `onUpdate` ② `MainActivity.onResume` ③ `MainActivity.onStop`（回桌面立刻看到新数）④ 每日 `AutomationWorker`；八枚统一 `updatePeriodMillis = 1800000`（30 分钟） | 账是在 App 里记的，只靠 `onResume` 会让改动等下一次进 App 才生效；系统轮询被 ROM 省电策略管着，只能当兜底 |
| 快捷方式 | `res/xml/shortcuts.xml` 静态两条（「记一笔」`action.NEW_BILL`、「查看统计」`action.STATS`），都只写 `pendingLink` | 单 Activity + `launchMode=singleTask` 可直接分发，不需要新组件 |
| 诊断包与日志落盘 | 日志单一出口 `DebugLog`（内存环 300 行 + `filesDir/logs` 文件日志 512KB 滚动 ×2 + 崩溃同步留档 `crash-*.log` 保留 5 份）；`Diagnostics.kt` 装包、`LogcatTail.kt` 按 tag 白名单捞系统日志并整行丢弃 SQL 与文件路径、`DiagnosticDao.kt` 出各表行数与 AI 健康度 | 日志的隐私边界只能在写日志那一层守：入口不接收账单内容，导出时就不必猜哪一行带了金额 |
| 长图渲染 | `Canvas` 直接绘制（复用统计四段的数据结构与 `TallyType` 字号），再 `Bitmap` → PNG 落 `Download/Tally`，`FileProvider` 分享 | 截屏方案要先把 Compose 树渲染到屏外，尺寸与滚动都不可控；直接画可控且能出高分辨率 |
| 关键词沉淀 | 记账页保存时若用户改动了机器预填的分类，给一条一次性沉淀动作，写入 `keyword_rule(source='LEARNED')` | 「越用越准」必须有一条零成本的路径，否则没人会去规则页手动加 |
| 导入判重 | `preview()` 传入 `existingFingerprints`；判重键沿用 `external_id` 优先、否则组合指纹；重复行在预览阶段单独成段并可切换「跳过 / 仍然导入」 | 重复行在预览阶段就说破，不让用户导完才发现 |

## 7. 外部接口

| 接口 | 形态 | 说明 |
|---|---|---|
| AI 服务商 | HTTPS `POST {base}/chat/completions` | 支持流式与非流式；部分网关对非流式请求也返回 SSE，客户端按流解析并聚合 |
| Android 通知 | 4 渠道：`reminder` / `automation` / `failure` / `system` | `POST_NOTIFICATIONS` 在通知设置页按需申请 |
| 桌面组件 | `RemoteViews` × 8（`ui/widget/TallyWidgets.kt` 一枚 + `ui/widget/InsightWidgets.kt` 七枚） | 只读 |
| 快捷方式 | `res/xml/shortcuts.xml` + `AndroidManifest` 的 `shortcuts` 元数据 | 静态两条 |
| 导入文件 | CSV（UTF-8 / GB18030）、XLSX | 三种内置来源，列映射只读 |
| 导出文件 | CSV / XLSX | 落公共 `Download/Tally`，可分享 |
| 备份包 | `.tally`（ZIP） | 系统文件选择器读写 |
| WebDAV | PUT / GET / PROPFIND | 手动快照与手动拉取 |
| 系统分享 | `ACTION_SEND` 图片 | 直达截图记账，应用内不显示该入口 |
| 诊断包 | `ACTION_SEND`（`text/plain`） | 设置 →「导出诊断包」；文本落公共下载目录后直接顶起系统分享 |
| 系统日志 | `logcat -d -v threadtime`（本进程 + crash buffer） | 尽力而为，Android 7 之后只读得到本 UID，厂商 ROM 可能直接返回空；出口过脱敏 |

## 8. 非功能设计

| 维度 | 做法 |
|---|---|
| 性能 | 首页/统计/分类页做过掉帧治理：一次查询喂多个区块、列表 key 稳定、避免组合期解码图片（缩略图采样解码）；长图渲染在 IO 线程且限制像素上限，避免 OOM |
| 隐私 | 无网络权限依赖之外的上报；小莉关闭时不发任何数据；发送内容最小化并在界面上写明；密钥不进备份与日志；通知不带金额；诊断包只带版本、开关与各表行数，不含任何一条账单内容 |
| 可靠 | 导入可整批回滚；备份先校验后替换；周期分期幂等；软删 + 回收站；库 identity hash 校验挡在打开之前，对不上就报错停住 |
| 可访问性 | 触摸目标 ≥ 48dp；选中态不只靠颜色；禁用态给出原因而不是隐藏；通知文案能读屏朗读，不用「▲▼」表意 |
| 可观测 | 应用内调试台（设置里打开调试模式）：300 行内存日志环 + 权限／引擎自检；日志同时落 `filesDir/logs`（512KB 滚动 ×2）；崩溃由全局未捕获异常钩子同步留档（保留 5 份）；Room 事务／查询的排队与执行超 200ms 写一行 `[Lock]`；以上都可由设置里的「导出诊断包」一次带走 |
| 体积 | 只打 `arm64-v8a`；新增坐标都是 AndroidX 轻量库 |

### 9.2 构建基线（实测跑通，勿单独升降任一坐标）

| 坐标 | 版本 | 约束来源 |
|---|---|---|
| Gradle | 9.6.0 | AGP 9.4.1 要求 ≥ 9.6.0 |
| AGP | 9.4.1 | Compose 1.12.x 的 AAR 元数据要求 AGP ≥ 9.1.0 |
| Kotlin | 2.3.21（AGP 内建） | AGP 9 起 `org.jetbrains.kotlin.android` 是硬错误 |
| Compose 编译器插件 | `org.jetbrains.kotlin.plugin.compose` 2.3.21 | 必须删除旧的 `composeOptions { kotlinCompilerExtensionVersion }` |
| KSP | 2.3.12 | 与 Kotlin 2.3 线配套，Room 走 KSP |
| Compose BOM | 2026.09.00 | 对应 Compose 1.12.1 |
| Room / WorkManager / OkHttp / ML Kit | 2.8.5 / 2.9.1 / 4.12.0 / 16.0.1 | Room 2.6.1 不兼容当前 KSP |
| compileSdk / compileSdkMinor | 37 / 0 | 本机平台目录是 `android-37.0`，只写 37 会解析成不存在的 `android-37` |
| minSdk / targetSdk | 28 / 37 | 产品约定 |
| JVM / abiFilters | 17 / 仅 `arm64-v8a` | 自用设备 |

三条落地约束：Gradle 发行版固定走 `https://mirrors.cloud.tencent.com/gradle/gradle-9.6.0-bin.zip`（`services.gradle.org` 在 307 跳转后连不上 CDN）；清单不写 `package=`；签名 debug/release 共用 `unified`，keystore 与三项口令只读 `local.properties`，缺失即构建报错。

### 9.3 交付路径

```powershell
.\gradlew.bat :tally-app:assembleDebug
# 产物 tally-app/build/outputs/apk/debug/tally-app-debug.apk
```

改代码 → `assembleDebug` → 提交推送 → 真机走查。每个改实体的批次，走查清单第一行必须是「旧包覆盖安装后数据还在」。

## 10. 已知架构级风险

| 编号 | 风险 | 处置 |
|---|---|---|
| R-01 | 没有迁移路，改实体就等于「设备上的旧库全废」：得先有 `.tally` 备份才能重建 | 不走迁移是主动取舍（见 §5）；风险处置改成「改实体前先导出 `.tally` 备份」，并把 identity hash 校验留在打开之前——报错停住而不是清库 |
| R-02 | ROM 杀后台导致提醒不响 | 前台补算兜底，文案不承诺准点 |
| R-03 | 附件文件只增不减 | 软删行 + 按 `sha256` 引用计数物理回收，与回收站共用同一个保留期设置，不另开一个清理入口 |
| R-04 | 跨账本迁移撞 `(rule_id, period_index)` 唯一索引 | 迁移前预检，冲突条目要求先解绑规则 |
| R-05 | 退款冲抵与「不计入收支」两口径叠加易混 | 口径页一张两行对照表；冲抵只作用于关联原单分类 |
| R-06 | 月起止日牵动四处，改一处漏三处 | 边界计算收口到 `domain/Period.kt`，页面不得自算 |
| R-07 | 长图渲染大图易 OOM | 限制最长像素、分段绘制、IO 线程执行 |
| R-08 | 外部入口（通知、快捷方式、组件）与深链、备份恢复的先后顺序易漏 | 判定只在导航层一处：外部入口只写 `NotificationLink`，由导航图翻译成一跳；记账页入口先收到首页再压页，参数不会被栈里的旧页盖住；恢复流程结束显式清掉外部入口 |
| R-09 | 去 AI 化后规则读不懂的表达没有补救 | 主动取舍，补救路径是小莉对话页，不加开关 |
| R-10 | 功能面宽，容易变成「什么都做一点」 | 按模块串行交付，每批完成即回写文档与状态，跨批不并行 |
| R-11 | 死代码与无用声明误导阅读者 | 已删：`ComingSoonScreen.kt`、`ui/common/SpeechModelDialog.kt.txt`、`settings.gradle.kts` 的 jitpack、`BillDraft.attachmentPaths` |
| R-12 | `keyword_rule` 曾带 `ledger_id`，与分类全局化口径不一致 | 已去掉，内置词组只认分类 `seedId` |

## 11. 在架构上明确不做

| 候选 | 判断 |
|---|---|
| 拆 Gradle 多模块 / 上 Hilt / 加 usecase 层 | 不做。单模块规模下收益为负，改动面还会牵连构建基线 |
| KMP 抽核心（为 iOS） | 不做。domain 层继续保持不依赖 Android，将来要做是加法不是重构 |
| 服务端、账号、冲突合并、删除墓碑 | 不做。同步预留列继续只写不读 |
| 本地向量检索与语义搜索 | 不做。只做条件层（时间、账本、来源、金额区间、排序），条件层是语义搜索的落点而不是竞品 |
| 无障碍服务与通知监听记账 | 不做。权限面与 ROM 适配成本远超收益 |
| 自定义图标上传、条件导出增强、平板/折叠屏适配、字体缩放 | 不做 |
| 多模型 AI 库与按任务路由 | 不做。一个当前模型的结论没变 |
| 收支日历、标签、部分报销、凭证多图、纯黑第四档、应用锁与生物识别 | 不做。前五项在范围裁定时砍掉；应用锁是系统级能力，不在 App 里做第二套 |
