## 1. 产品目标

**只存在手机里的记账本。**不引入账号、服务端、账户层与资产层——这条边界定死，本文所有取舍都以它为先决条件。

| 目标 | 度量方式 |
|---|---|
| 记一笔足够快 | 连记第二笔起 ≤ 2 步（再记留在本页） |
| 数据可信 | 金额以分存储、统计口径唯一、批量半成功逐条报因 |
| 离线可用 | 记账、统计、导入导出、备份恢复全程无网络 |
| AI 可选不绑架 | 关闭小莉时界面无 AI 痕迹，语音与截图走端侧仍可用 |
| 迁移有路 | 三源导入 + 导出 + `.tally` 加密备份，换机可恢复 |
| 不用它就会被习惯打断 | 周期/分期到期、执行失败、当日未记账三类情形，用户在 24 小时内一定收到一条可点达的通知 |
| 找回有路 | 删除是软删，回收站按删除日分组，保留期可设 |
| 借出去的手机不丢人 | 通知在锁屏预览态不带金额与分类名；「递出去手机」这件事交给系统级应用锁，App 不再套一层 |
| 边界不破 | 全仓不出现账户、余额、云同步、多端合并四个概念；`BillType.TRANSFER` 保持不可达 |

## 3. 非功能需求

| ID | 需求 | 判据 |
|---|---|---|
| NFR-01 | 金额精度：分单位 `Long`，禁止浮点参与业务计算 | 达成 |

| NFR-08 | 存储上限：凭证**一笔一张**、单张限边长 WebP；截图批量一次 ≤ 9 张、对话一次 ≤ 3 张；软删超保留期的附件按 `sha256` 引用计数物理回收 | AC-11、AC-30 |
| NFR-09 | 性能：首页/统计/分类/回收站首屏无可感知掉帧；列表 key 稳定；图片采样解码，不在组合阶段解原图；长图渲染在 IO 线程且限制像素上限 | 真机走查 |
| NFR-10 | 一致性：新页面复用同一套组件与换算（1px≈1dp、px×1.2=sp），不另起一套视觉；同一标记在记账页 / 卡片 / 批量三处图形与口径一致 | 设计图逐屏对照 |
| NFR-11 | 提示语预算：每屏 ≤ 1 条灰字说明；提示走贴底自动收起的 `TallyToast` | 设计图评审 |
| NFR-12 | 无障碍与触摸：目标 ≥ 48dp，选中态不只靠颜色，禁用态给出原因而不是隐藏 | 走查 |
| NFR-13 | 兼容：minSdk 28（Android 9）起，target 37，仅 `arm64-v8a` | 达成 |
| NFR-14 | 可观测：应用内调试台（300 行内存日志环 + 权限／引擎自检）；日志同时落 `filesDir/logs`——512KB 滚动 ×2 份，崩溃同步留 `crash-*.log` 保留 5 份；迁移日志、通知发送结果、清理任务回收量、Room 事务／查询的排队与执行超 200ms（`[Lock]`）都写 `DebugLog` | 达成 |
| NFR-15 | 不做自动化测试的既有工作方式沿用：改代码 → `assembleDebug` → 提交推送 → 真机走查 | 交付流程 |

## 4. 接口需求

| 接口 | 规格 |
|---|---|
| AI 服务商 | OpenAI 兼容 `POST {base}/chat/completions`；支持流式；必须容忍非流式请求返回 SSE、容忍空 `content`；工具调用三级降级（tools → response_format → 文本围栏） |
| 导入文件 | 模板 UTF-8 CSV / XLSX；钱迹 XLSX；支付宝 GB18030 CSV。按表头识别列数并可原样读回 |
| 导出文件 | CSV / XLSX，含 ID 与已报销金额，落 `Download/Tally` |
| 备份包 | `.tally` ZIP：`manifest.json`（带 `formatVersion` / `appVersion`）+ `data.enc`（AES-256-GCM，PBKDF2 120k）+ `attachments/` |
| WebDAV | 标准协议，手动 PUT / GET / PROPFIND |
| 系统分享 | `ACTION_SEND`（image/*）→ 截图记账 |
| 系统语音 | `RecognizerIntent` 与 `SpeechRecognizer` 双路径 |
| 通知 | 4 个渠道：提醒、自动记账、失败、系统 |
| 桌面组件 | 平台 `RemoteViews`，**八枚**只读，点击带 `NotificationLink` |
| 快捷方式 | `res/xml/shortcuts.xml` 静态两条 |
| 长图分享 | `Canvas` → `Bitmap` → PNG，经 `FileProvider` 分享；无 PDF |
| 后台任务 | WorkManager 每日一次 `AutomationWorker`，承载补执行、提醒、清理 |

## 5. 数据需求

见数据库设计文档：15 张表、`version = 1`（无迁移链）、软删与同步预留列、统计口径过滤条件、幂等唯一索引、改实体后按备份包重建设备的规矩。

## 8. 验收方式

本项目无自动化测试。验收 = 上述 `AC-xx` + 真机走查清单（交互验证一律用模拟器）。纯逻辑（房贷排期、金额解析、批量口径、脱敏、迁移）靠把同一段算法转写成 node 脚本实跑来验，不靠肉眼读代码。

任何新需求先补齐范围与验收条目再开工；口径类改动必须先写进口径表再上界面。
