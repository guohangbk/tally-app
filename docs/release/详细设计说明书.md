## 1. 记账页

**入口**：`＋` 短按 → 路由 `bill/new`；账单卡片「修改」→ `bill/edit/{id}`；小莉卡「改一下」→ `bill/new` 带预填；`＋` 上臂语音、左臂截图 → 带机器预填进同一页。
**实现**：`ui/bill/BillEntryScreen.kt` + `BillEntryViewModel`（`ui/bill/BillViewModels.kt`）。

全站只有这一张记账表单，新增 / 编辑 / 再记 / 机器预填共用，**不新增第二个记账页**。

| 项 | 设计 |
|---|---|
| 表单 | 支出 / 收入两枚 tab、分类选择器、金额、日期、备注、报销 / 图片 / 排除三枚 chip |
| 键盘 | 4×4 十六格 `123⌫ / 456− / 789＋ / 再记 0 . 保存`，格 42dp 等宽等高，保存固定右下 |
| 算式 | `−` `＋` 进入算式态，连续输入形成 `a ± b ± c`；无等号键，保存即结算；结果为负整行转支出红并禁用保存 |
| 清空 | 长按 `⌫` 清空金额与算式 |
| 再记 | 保留分类 / 类型 / 标记 / 日期，清金额与备注与图片；停留本页并显示会话计数 |
| 编辑态 | 键盘位置不变，左下键从「再记」变「放弃」；未改动内容时保存置灰；放弃始终可点，动过内容离开时拦一道 |
| 默认分类 | 支出空白进入时直接落在「三餐」；三餐被归档 / 删除才回落记忆值 → 全机笔数最多的一级。收入没有三餐，仍按记忆值。切收支时重新取一次。「再记一笔」与语音 / 截图带进来的预填分类优先，不被默认值覆盖 |
| 分类记忆 | 保存后写 `last_category_l1/l2`（DataStore，全机一对） |
| 时刻 | 日期 chip 由「今天 / 10-14」变成「10-14 12:26」形态（精度为时刻时），点开 §2 选择器。精度为「日」时保存把时刻归零到本地 00:00，避免同一天出现 0 点与 12 点两种键 |
| 凭证图 | `bill_image_enabled` 开启才出现入口，**一笔一张**；选中即压缩 WebP 并算 SHA-256；再选即替换，可移除 |
| 退款 | 支出类型下多一枚 chip「退款」，点开选原单（§4）；选中后 chip 点亮。不选原单时这笔就是普通支出；旧导入的 `is_refund=1` 无原单行以青灰态点亮，可在同一弹层补挂 |
| 校验 | 金额为空或非正 → 不能保存；未来日期给「这是一笔未来账单」提示但仍允许保存 |
| 输入法 | 弹出时不整页顶起，也不挪动键盘位置 |
| 卡片出口 | 「查看统计」跳到已按条件筛好的搜索页，而不是裸统计页 |

**沉淀**：语音 / 截图 / 小莉带来的关键词随路由进记账页；用户把机器预填的分类改动并保存成功后，根部弹一条 6 秒气泡「以后「打车」都记到 交通 · 打车」+「确定」；点它写 `keyword_rule(keyword, category_id, source='LEARNED')`。分类写全路径（有父级时「一级 · 二级」），句子是陈述句不带问号。气泡每句话只出现一次，动作挂在应用级 `KeywordSediment` 上，不打断连记。

**输出**：`BillRepository.save(BillDraft)`，单事务写 `bill` + `attachment` + 退款累计校验。

## 2. 时刻选择器

`ui/common/TallyDateTimePicker.kt` 的 `TallyDateTimePickerDialog`，自带月历网格与「时 / 分」两列滚轮，不包旧日期弹层。

| 项 | 规格 |
|---|---|
| 触发 | 记账页（新建与编辑）的日期 chip；精度为时刻时 chip 显示「今天 12:26」形态 |
| 组成 | 顶部「今天 / 昨天 / 前天」快选，中间月历网格，精度为 `DATETIME` 时下方两列 24 小时 × 60 分钟滚轮，底部「现在」与确定 / 取消 |
| 精度联动 | `time_precision = DATE` 时不出现滚轮，只有日期；`DATETIME` 时滚轮预填账单当前时分 |
| 输出 | 本地时区的 `epochMillis`，写 `bill.occurred_at` 与 `time_precision` |
| 边界 | 分钟步进 1，不做秒；编辑历史账单时精度跟着该行走，改完仍按原精度保存 |

## 3. 金额与文本解析

**金额**：`ImportParsers.parseSignedAmount` 与速记 `QuickNoteRules.findAmounts` 都以十进制定点处理——先清洗千分位与空白，再按小数点拆整分，四舍五入到「分」，全程不经过 `Double`。带符号输入（`-12.5` → −1250）由统一的 `parseAmount` 处理，导入器不再单独转换负数；速记层不接受负号。

**速记解析顺序固定**：日期 → 时间 → 金额 → 关键词分类 → 备注，前一步吃掉的字符区间会被扣掉，因此「10月13日」不会被读成 13 元、「下午3点」不会被读成 3 元。解析不出来的字段进 `ParsedQuickNote.missingFields`，草稿页要求补。检出多笔时只提示拆分，不自动拆。

**阿拉伯数字混写**：`amountRun` 的阿拉伯分支可继续吃「角 / 毛 / 分」及其后数字，「29块8毛5」= 29.85 且不再切出多余的 5.00 触发误报拆分；中文数字路径已验证正确。

**关键词分类**：`keyword_rule` 表按 `priority` 匹配（用户规则 20 / 内置 10），目录由 `KeywordRuleRepository.observeCatalog()` 订阅出来——合并 `category.observeActiveAll()` 与 `keyword_rule.observeAll()`，所以刚沉淀、刚手加、刚改绑的词**当场生效，不必退出重进**。内置词组的绑定只认 `DefaultCategoryTree.seedId(type, slug)` 的种子 id，不做名称兜底；id 不存在（用户重建过分类树）即判该组失效并在关键词页显示警示态。

## 4. 退款与原单关联

**入口**：记账页「退款」chip → `ui/bill/BillRefundSheet.kt`（底部弹层，与账本 / 分类弹层同一套组件）。

**选原单**：列表候选 = 「近 90 天、支出、未退满」的账单，跨账本（行上写账本名），行上显示 `分类 · 日期 · 账本 · 还能退 ¥x`；已选原单即使滑出窗口或已退满也固定显示在首行，底部可「取消关联」。选中心仪原单时，分类跟原单走、金额空着就填剩余可退。

| 规则 | 处理 |
|---|---|
| 一笔可被多次退款 | 每次退款是独立 `bill` 行，`refund_of_bill_id` 指向同一原单 |
| 累计校验 | 保存前在事务内重读原单已退累计，`+ 本次 > 原单金额` 即拦并显示「最多还能退 ¥x」 |
| 原单已删 | 回收站里的原单不作为候选；原单被删除（软删或彻底删除）时，指向它的退款 `refund_of_bill_id` 置空并保留 `is_refund`，回到「未关联原单」的中性行 |
| 跨账本退款 | 允许，候选行上写原单所在账本；冲抵按原单所属分类算，不按退款所在账本 |
| 展示 | 原单详情卡显示「已退 ¥x / ¥y」并逐笔列出退款（点行跳到那笔）；退款行带「退款」徽标（`ui/design/BillBadges.kt`）与「退自 …」卡（点行跳回原单） |

**口径**：退款行仍是支出类型，但既不计支出也不计收入，在退款自己的周期里从原单分类的支出中扣减（§7）。

## 5. 账单浏览与批量

| 环节 | 设计 |
|---|---|
| 分组 | 首页按 `occurred_at` 的本地日期分组；`time_precision = DATETIME` 时按「到时和分」粒度分组 |
| 月份切换 | 左右箭头翻月一次一格；点月份文字开 `TallyMonthPickerDialog` 直跳；切月只重算当月查询 |
| 顶栏 | 抽屉 · 标题（切账本）· 统计 · 搜索四个触点；月份行在汇总条上方 |
| 汇总条 | 本周期支出 / 收入 / 笔数 / 日均 / 结余；`excluded_from_stats` 不进汇总，单独提示「另有 N 笔不计入收支」 |
| 预算进度 | 汇总卡正下方一条细进度（见 §11） |
| 选择态 | 长按行进入；行首勾选框 + 底部深色动作条（`SelectionBarShell`，顶部 20dp 圆角、左上「N 笔」、图标+文字的动作格）；`BackHandler` 优先取消勾选 |
| 批量动作 | 见 §12 |
| 详情 | `BillDetailSheet` 底部弹窗，只读 + 动作行（修改 / 复制 / 退款 / 报销 / 删除），首页、搜索、报销、回收站复用同一组件；**不在弹层里就地编辑**，要改就跳记账页 |
| 删除 | 确认框说清后果 → 软删 → 弹层当场关掉 → 贴底气泡只报「已删除，可在回收站找回」 |

**撤销整体下线**：回收站能单条恢复、整组恢复、长按批量恢复，「靠一条长气泡兜命」就没有存在理由了。`BillBatchViewModel` 的 `UndoBundle` / `undo()` / `UNDO_WINDOW_MILLIS` 与详情弹层的 `undoDelete` 全部删除，删除确认框里那条「软删除 · 8 秒内可撤销」一并去掉。连带清掉因此变成死码的 `BillRepository.snapshot/restore` 与 `BillDao.restore`——回收站走 `restoreRecycled` + `restoreByBills`（按 id 批量置空），不需要先取快照再整批 REPLACE 回去。

## 6. 分类与账本

| 操作 | 规则 |
|---|---|
| 层级 | 一级 `parent_id = null`；二级必须挂一级且同收支类型；两级为限 |
| 排序 | `sort_order` 取相邻中点，不重编全表；拖拽引导只首次显示 |
| 归档 | `is_archived` 只表示**自身**归档；子树可见性由 `CategoryDao` 的 active-only 查询按父级状态判定。归档后不进记账选择器，历史账单仍计入统计；恢复可单个执行 |
| 删除 | 有账单引用时必须选迁移目标（同收支类型、同层级、未归档、非自身），笔数按**全部账本**口径；0 笔直接删 |
| 彻底删除 | 仅归档区且 0 笔可执行 |
| 图标 | 只存 `icon_key`；二级独立不继承；写入前过 `IconLibrary.isKnown(key)` 校验，未收录键**拒绝写入**并内联提示「没有这个图标，试试：…」。首字 tile 保留为**渲染兜底**（针对备份包带回的历史脏值），不再是写入路径的产物 |
| 账本 | 新建账本复用全局分类树；设默认唯一；归档账本不出现在切换列表；删除必须先迁移账单且不能删默认 |
| 账本图标 | 复用 `IconLibraryPage`（`IconLibraryMode` 有一档 `LedgerIcon`），值域 136 键。图标库页挂在账本页的 back stack entry 上取**同一份** `LedgerViewModel`，保存的键写回编辑弹窗草稿；弹层对 `initialIcon` 做 `LaunchedEffect` 回填，选完立刻换脸。卡片左缘是 44dp 纸面 `IconTile`（纸面底 + 1dp 描边 + 墨色字形），与分类页一级卡片同一张瓦 |
| 切账本 | 弹层先摊开影响面：首页与统计只算这本、记账落这本、搜索默认这本；分类树不随账本变。「全部账本」行用固定的 `select` 形 |

## 7. 统计

**实现**：`ui/stats/StatsScreen.kt` + `StatsViewModel.kt` + `data/repository/BillRepository` 的聚合查询。

- 一页四段（收支总览 / 分类报表 / 排行 / 趋势）共用**一次**查询快照：换账本、换周期、换区间、换收支只重算数字，不换页。**新增维度只加算不加查询**——区间、分桶、星期、二级都从同一个 `observeStatistics(request)` 快照派生。
- 统一过滤：`deleted_at IS NULL AND excluded_from_stats = 0`；被排除笔数与金额单独统计并在界面上明示。
- 维度行是「月 / 年 / 区间」三段。点「区间」开 `StatsRangePicker.kt`：预设「本月至今 / 近 7 天 / 近 30 天 / 今年至今」点一下即生效，也可点起、止两行各开 `TallyDatePickerDialog`。区间**含起止两天**（内部仍是左闭右开），顶栏写「9/12–10/11」，跨年带年份；翻页按区间天数整体前后挪。
- 分组粒度只在区间维度出现「日 / 周 / 月」小切换。自动档 ≤ 62 天按日、更久按月；手动选的档随请求下发，折线、逐桶表、日均分母共用同一档。周从区间起点起每 7 天一段，不对齐自然周。
- 支出视图可开「剔除未报销」，开启后待报销金额不计入支出；口径页写明这是视图开关而非数据变更。
- 月维度：日粒度报表（支出最高的一天、无支出天数）；年维度：月粒度报表（全年最高、月均支出、支出最高的一月）。
- 分类报表按金额排序、可折叠，一级行可展开二级行（金额、占本类比例、笔数）；点饼图扇区会连一级行一起展开。占比过小的分类合并成「其他」一级行，点开看被合并进去的原始分类。
- 下钻弹层 `CategoryDrillSheet.kt` **只有两层**：一级弹层列拆分（二级按金额在前，直接挂一级的钱沿用一级分类名、排在最后），末级直接是账单列表。**末级不再套分类头**，没有「直接」标题、没有返回、没有 ⋯；点账单行进详情。`StatsViewModel` 用单个 `CategoryDrill?` 表示当前层，不维护路径栈。
- 日 / 周 / 月弹层复用 `BillListSheet`：顶部一行 12.5sp「日期或周期 · N 笔 · ±合计」+ 关闭，正文是首页同款 `BillRow`（分类 · 备注 · 金额）。合计取同一份 `dailyTrend` 的桶数字，与表格同源。
- 趋势：区间维度用折线（月/年仍是柱状），折线无填充，点按落点选最近一桶，选中点下方给金额；横轴只标首、中、末三个桶（下标重复时只印一次），**只有一个桶时不画图**。
- 星期分布：分类排行下方一张卡，周一到周日七根**日均**柱（不是饼图），卡头写「最高 周X · 日均 ¥x」——柱高与标题同源；日均分母是该星期几在区间内出现过的天数（只算到今天）。
- 退款冲抵：汇总函数入口统一，净支出 = 支出 −（关联到该分类的退款）；「不计入收支」仍按原语义。
- 合计「至 X 月」：本年取到今天所在的月，历史年取满 12 月。
- 账单页汇总、统计四段、搜索合计、导出文件、预算进度引用同一份口径实现，页面不各自算一套。

## 8. 搜索

`BillFilter`（`domain/model/BillModels.kt`）字段：

```kotlin
keyword, type, ledgerId, categoryL1Id, categoryL2Id, source,
startAt, endAtExclusive,
amountMinMinor: Long?, amountMaxMinor: Long?,
sort: TIME_DESC | TIME_ASC | AMOUNT_DESC | AMOUNT_ASC
```

**界面**：搜索页默认只摊开关键词与收支类型两格，其余条件（时间、账本、来源、金额区间、排序）收在「更多筛选」里；顶部一行「筛选」按钮 + 已生效条件数徽标；**收起时已生效的条件写在开关下面**。条件即时生效，弹层底部「清空」。

**结果**：合计行显示笔数与支出 / 收入，走全量口径；四条排序共用同一条 `SEARCH_ROWS`，只换 `ORDER BY`；超过 1000 笔在末行显示「列出 N 笔 · 还有 M 条未列出」并给跳转，不静默截断。结果内可直接全选做批量。

## 9. 周期与分期

**排期算法**（`domain/schedule/RecurrenceSchedule.kt`）：策略按单位分派——`DAILY`、`WEEKLY`（对齐星期）、`MONTHLY`（`clampToMonth` 处理 31 日等越界）、`LAST_DAY_OF_MONTH`、`YEARLY`。两个入口：`previewOccurrences`（新建页预览，不落库）、`dueOccurrences`（从 `next_due_at` 推进到今天的应执行区间）。

**执行**（`data/automation/AutomationService.kt` + `work/AutomationWorker.kt`）：WorkManager 每日一次；App 启动、回前台、打开周期页时调 `catchUp(autoLimit)` 补执行；每次生成写 `bill.recurrence_rule_id + period_index`，唯一索引 `(rule, period)` 兜底幂等，重复触发不多记。补记保持「账单日期 = 应执行日」，不挪到今天。

**一个任务一个事务**（`AutomationService.executeAll`）：原来整批一个事务，一条坏规则会把所有到期任务一起回滚，Worker 每天重试、每天静默失败，而且没有任何人知道。现在每个任务独立提交，失败的留下 `FAILED` 明细，成功的照常入账，通知说的是「哪几条、为什么」。

**普通分期**（`InstallmentSchedule.compute`）：输入本金、期数、手续费与模式（`NONE` / 并入每期 / 单独成期），算出每期金额与末期尾差，保证 `Σ期 = total`；间隔可设每月 / 每 2 月 / 每季 / 每半年 / 每年（`interval_months = 1/2/3/6/12`），日期推进 `first.plusMonths((index−1) × interval)`，31 日自动压到当月最后一天。预览列表要能看出跨季（例：首期 10-31 → 第二期次年 1-31，显示对齐后的实际日期）。提前结清先确认再停止后续生成，已生成账单保留；单期账单就是普通账单，可单独改删。

**房贷**：表单顶部切「普通分期 / 房贷」。房贷字段为贷款金额、期数（月，上限 480）、等额本息 / 等额本金、LPR + 加点（BP），年利率 = LPR + 加点，范围 0–30%。

- 等额本息：月利率 `r = bp / 120000`，月供 `P·r·(1+r)^n / ((1+r)^n−1)`，每期利息按剩余本金四舍五入到分，末期用余额收口。
- 等额本金：每期本金 `P / n`，利息按剩余本金逐期递减。
- 两者都保证 `Σ本金 = 贷款金额`、`Σ(本金 + 利息) = 总额`；`r = 0` 时直接按本金均摊。

**改利率**：并入编辑页，不单开一页。仅还款中的房贷显示利率区；LPR 与加点在原位改，下方实时给「改后每期 / 少 X 多 X」与「改前 · 剩余利息（当前 …）」，并写明「只影响未生成的 N 期，已入账的 M 期不改」。保存时先把名称 / 账本 / 分类 / 备注写进计划，若利率真的变了再追加 `{from: generatedPeriods + 1, bp}` 进 `rate_changes_json`，用剩余本金与剩余期数重算后续期并同步 `total / per_period / tail`。

**编辑边界**：新建与编辑共用 `InstallmentFormScreen(planId)`。编辑态贷款金额、期数、首期入账日、手续费是**虚线锁行**——它们决定了已生成账单，改了就会让历史对不上；名称、账本、分类、备注、房贷利率可改。计划读不到（已被删除）进 `missing` 态，页面只有空态与「返回列表」，不出现任何保存类提示。

**列表卡片**：`InstallmentCard` 三行 + 一条操作行。第一行 `IconTile` + 名称 +「分类 · 每期 X（· 末期 Y）」+ 右端 `n/total 期`；第二行账本名 `TallyTag(OUTLINE)` + 至多两枚状态标签（利率、手续费成期方式、尾差异常、已结清）+ 「已入账 N 期」；第三行进度条，结清转石板灰。操作行是 `明细 / 补记 / 编辑 / ⋯` 四等分，提前结清与删除在 ⋯ 的 `DropdownMenu` 里，结清后补记不可点。本期应还、剩余本金、下期本金**不上卡**。

**明细弹层**：`ModalBottomSheet` 顶部三格指标——房贷为本期应还 / 剩余本金（注：已还 X）/ 下期本金（注：利息 Y），普通分期为本期应还 / 已还金额 / 剩余期数。房贷表多「本金 / 利息」两列，状态列区分已入账 / 末期 / 手续费 / 待生成；表尾 `Σ 各期 = 总额 ✓`，不平时写「尾差异常」并转支出红。底部「关闭 / 补记到期」。弹层限高，头部与按钮固定，只滚表格。

**补记到期**：点补记先弹确认框，不直接写库。框内给可补期数、期号区间、合计（房贷含利息）、最早一期与过期天数，说明「补记后仍可在明细里逐期改或删，同一期不会被重复入账」。可补期为 0 时主按钮置灰、文案「没有可补的期」。补记出的账单日期仍是应还日；同一期靠 `(plan_id, period_index)` 幂等。从明细弹层发起时先关弹层再开确认框，避免两层遮罩叠着。

## 10. 报销

纯状态流：`reimbursed` 取 `NONE / PENDING / DONE`，只作用于支出账单。确认报销一次改多笔并记 `reimbursed_at`；撤销回到 `PENDING` 但保留原日期留档。

**金额与统计不因状态变化**（除非用户在统计页开「剔除未报销」视图开关）。不做部分报销累计——`reimburse_amount_minor` 这一列从未加过，批量报销仍是整笔置状态。

钱迹导入的「报销记录」行映射为 `is_reimbursement = true` **且** `excluded_from_stats = true`。开关 `reimburse_enabled` 默认关闭，关闭时记账页不出现报销字段、管理页显示未开启说明。

## 14. 每月起始日与 `domain/Period.kt`

```kotlin
data class PeriodRange(val startAt: Long, val endAtExclusive: Long) {
  fun lengthDays(): Int
  operator fun contains(epochMillis: Long): Boolean
}

object Period {
  const val DEFAULT_START_DAY = 1      // MIN 1 / MAX 28
  fun normalizeStartDay(day: Int): Int // coerceIn(1, 28)
  fun monthRange(anchorMillis: Long, startDay: Int = 1): PeriodRange
  fun monthStart(year: Int, month: Int, startDay: Int = 1): Long
  fun yearRange(anchorMillis: Long): PeriodRange
  fun dayRange(startMillis: Long, endExclusiveMillis: Long): PeriodRange
  fun shift(epochMillis: Long, deltaMonths: Long): Long
  fun shiftDays(epochMillis: Long, deltaDays: Long): Long
  fun daysBetween(startMillis: Long, endMillis: Long): Int
  fun label(range: PeriodRange, startDay: Int = 1): String   // "2026年10月" / "10/15–11/14"
  fun rangeLabel(startMillis: Long, endExclusiveMillis: Long): String
  fun key(range: PeriodRange): String                    // AI 报告周期键，两端含当天
  fun toDate(epochMillis: Long): LocalDate
}
```

`monthRange` 的结果由「不超过 anchor 的最近一个起始日」与「一个月后的同一天」构成：`anchor` 落在 5 号、起始日 15 号时，返回的是 4/15–5/14 那一段。起始日取 1–28，短月不需要「月末对齐」这条额外规则。

| 生效点 | 行为 |
|---|---|
| 首页汇总条与周期切换 | 「本月」= 当前周期段；翻页按周期段而非自然月，标签在起始日非 1 号时写「10/15–11/14」 |
| 统计 | 月维度的锚定与翻页引用 `monthRange`，与首页同一边界；年维度、区间维度不走这条 |
| AI 月报 | `StatsRequest.startDay` 带进结算，`month_key` 跟着窗口走，改起始日等于换一段区间重算一份；同期取整段上期 |
| 预算 | 周期比较用同一区间；`YEARLY` 预算用 `yearRange` |
| 每日提醒 | **不受影响**（按自然日判定），避免「这个月还没记过账」的歧义 |

设置项在「记账偏好」段，值域 1–28（**不允许 29–31**，避免短月歧义），存 `app_setting.month_start_day`，默认 1。

## 15. 通知体系

**落点**：`data/notify/TallyNotifier.kt`（渠道枚举 `TallyChannel` 与发送出口）、`data/notify/NotificationLink.kt`（点达去处）、`data/notify/ReminderCoordinator.kt`（四类提醒的评估与发送）。渠道不单开一个文件——四个渠道的定义与「怎么发」是同一件事，拆开只会让 id 字符串两处各写一遍。

**不新增 Worker**：提醒全部挂在既有的每日 `AutomationWorker` 上（启动、回前台 `runNow`、每日定时三条触发路径共用），`AppGraph.reminderCoordinator.runBackground()` 是这三条路径唯一的入口。提醒与补执行算的是同一批数据，分成两个 Worker 就是各读一遍库、各判一次「今天发过没有」，还会发出两条互相不知道存在的通知。

| 渠道 | 内容 | 触发 | 幂等 |
|---|---|---|---|
| `tally_reminder` 每日提醒 | 「今天还没记账」+「昨天记过账，今天还没有 / 已经 N 天没有新账单 / 还没有一条账单」 | 本地时刻过了设定小时（默认 20:00）后的第一次后台评估 | DataStore `last_unlogged_reminder_at` = 本地日期串，同日一次；当天补记了账就把挂着那条 `cancel` |
| `tally_automation` 自动记账 | 单条「房租已记入 · ¥2,400.00 · 日常账本 · 10 月 20 日」；同批多条聚合成「N 笔自动账单已记入」；超阈值「N 笔到期，等你确认」；分期「车贷第 3 期明天到期 · 应还 10 月 30 日」 | 补执行结果（已记入 / 待确认）＋ 分期下一期落在今天或明天 | `recurring_rule.last_reminded_at` / `installment_plan.last_reminded_at` 同日不重发；tag 带日期，重复触发是更新不是堆叠 |
| `tally_failure` 执行失败 | 「N 条任务没能执行」+「名字：原因」，原因取异常链最里层 message | 单个任务的独立事务回滚 | 与到期共用同一枚游标（每任务每日一发）；下一次跑成功自动 `cancel` |
| `tally_system` 系统 | 「回收站清理了 N 笔 · 释放 X KB · 到期后不再能找回」 | 每日清理有实际产出时 | tag 带日期 |

**判定口径**：「今天没记账」= 本地自然日内不存在 `deleted_at IS NULL` 的任意账单。不看收支方向（当天只记一笔收入也算在记），不看 `excluded_from_stats`；软删进回收站的不算记过。

**到期文案只说明天与今天**：已经过期的那一期是「等确认」或「执行失败」的口径，由另外两条通知说，不该在这里被写成「今天到期」。

**授权**：`POST_NOTIFICATIONS` 只在提醒与通知页要，进页面即创建四个渠道；被拒后不自动重弹系统框，卡片里那颗「开启通知」是唯一入口。权限没给时四类一条都不发、**也不写游标**，授权之后当天该补的还能补上。总开关关掉时 `cancelAll()` 收掉本 App 挂着的全部通知。

**点达**：`TallyNotice.link` 带一个 `NotificationLink`——只说去处，不抄路由语法；`TallyNotifier` 把它编码成 intent 的两个 extra，`MainActivity` 还原后写进 `AppGraph.pendingLink`，`ui/navigation/NavDeepLink.kt` 那张映射表在导航层翻译成一跳。账单详情是首页那张弹层而不是独立一页，所以先整栈回退到首页，链接留给首页消费并清空。

**隐私**：每条通知都配一份 `publicText`，经 `setPublicVersion` 挂在私密通知上；`show_amount_on_lockscreen` 默认关，关着时锁屏上只有一句不带金额与分类名的话，公开那份不带 `contentIntent`。这一条不依赖应用锁（App 不做应用锁），任何时候都成立。

**不做**：每周备份提醒仍是 `BackupScreen` 上的一行文案，没有变成通知——四类里不含它。

## 17. 导入与判重

```text
选来源 → 选文件 → 编码与表头定位 → 列映射（内置只读）
      → 行级解析 ParsedBill → 校验（日期/金额/类型/分类）
      → external_id 或 fingerprint 去重 → 预览与异常行
      → 选目标账本 → 单事务写入 → 月度笔数与金额对账 → 报告
```

| 来源 | 细节 |
|---|---|
| 模板 | UTF-8 CSV / XLSX，12 列；也识别导出的 13 列（首列 ID） |
| 钱迹 | XLSX 按表头识别；账户、手续费、优惠券、标签列忽略并列名说明；**先判钱迹再判模板**，否则「报销记录」映射会失效 |
| 支付宝 | GB18030 CSV，跳过前言（前 8 行）与无名尾列；必须指定目标账本 |

**判重**：预览前 `ImportService.existingKeys()` 一次取全库已有 `external_id` 与 `fingerprint`，`preview(table, existing)` 据此标重复；执行时按同一套键逐行再查一次，预览与实际写入不会各判各的。

```text
预览页四格：可导入 N · 重复 M · 异常行 K · 报销记录 R
重复区标题：「M 笔重复 · 已导过 X · 文件内 Y」，可展开明细
明细每行「日期 · 备注/分类 · 金额 · 文件内重复 / 已导过」
重复账单分段：跳过（默认） / 仍然导入
选「仍然导入」→ TallyConfirmDialog 写明同一笔会出现两条，合计会变大
```

判重键 `dedupeKey = externalId ?: fingerprint`，且**只认选中的那一把**：有外部 ID 就只比 `external_id`，没有才比组合指纹，不能交叉命中。文件内的重复取首个出现的行。手工账单 `fingerprint = null`，所以只会命中此前导入过的行。对账只比去重后实际计划写入的行，`import_batch.duplicate_rows` 记重复数并入 `report_json`。

**报告标题**三档：正常写入且对账平 →「导入完成」；事务已提交但分月合计不平 →「已写入，对账不平」；异常中断回滚 →「导入未完成」。文件名取 SAF 的 `DISPLAY_NAME`，不显示文档 ID。

异常行可就地修或跳过继续；对账不平可整批回滚；`import_batch` 存 `report_json` 供复盘。完成页给三个后续动作（再导入 / 回账单 / 批量修正本批）。

## 18. 导出

13 列 = `ID` + 12 列模板字段（时间 / 账本 / 分类 / 二级分类 / 类型 / 金额 / 币种 / 备注 / 已报销 / 记账者 / 账单图片 / 关联账单）。条件：时间范围（本月 / 本年 / 全部 / 自定义起止）、账本（全部或指定）、格式（CSV / XLSX）、是否写图片路径列（默认不写）。产物落公共 `Download/Tally`，可分享。导出的 CSV 可被模板来源原样读回（ID 参与去重）。

## 19. 备份与 WebDAV

| 环节 | 设计 |
|---|---|
| 生成 | 写 `manifest.json`（`formatVersion`、`appVersion`、时间、笔数、是否含图、哈希）→ 序列化 15 表 → AES-256-GCM 加密（密钥 PBKDF2 120k）→ 打包 ZIP → 落 `Download/Tally` |

| 登记点 | 四处必须同步，漏一处即恢复后静默丢数据：`BackupJson.kt` 的 `BackupSnapshot` 与 encode / decode、`BackupService.kt` 的 `loadSnapshot` / restore 插入 / `clearAll`、`TallyDatabase.kt` 的 entities |
| 与诊断 DAO 的关系 | `DiagnosticDao` 是纯查询 DAO（`@Query` 计数与 AI 健康度），**不进 entities、不改表结构**，所以 Room 的 identity hash 不变、`version` 不抬、备份登记点不受影响。见 §28.2 |

| 入口 | 首次引导首屏「导入 Tally 备份」与设置 → 备份与同步 |
| WebDAV | 手动上传 / 下载 / 分享快照 + 每周提醒文案；无后台静默同步、无双向合并 |

## 20. 附件与图片

- **采集**：记账页选图（一枚）、截图草稿保存、小莉对话图。
- **处理**：采样解码 → 限边长 → WebP 压缩 → SHA-256 → 写 `files/attachments/`，库中存相对路径与尺寸；同内容按哈希去重。
- **展示**：列表与气泡用 `ImageThumbnail` 压好的缩略图，按需采样解码，**绝不在组合阶段解原图**。大图走 `FullScreenImageViewer`（`ui/design/ImageViewer.kt`）——账单附件与对话图片共用同一组件、不共用状态。
- **生命周期**：账单软删时附件行一起软删；物理文件按 `sha256` 引用计数回收，零引用且超保留期才删，先删文件后删行，失败可重跑。
- **上限**：凭证一笔一张；截图批量一次 ≤ 9 张（那是 9 张截图 → 9 笔待确认账单，不是一笔九张）；对话一条消息 ≤ 3 张。

## 21. 语音与截图

**语音**：`SystemSpeechPort` 走系统 `SpeechRecognizer`；`RECORD_AUDIO` 拒绝或引擎不可用（部分机型 `error=9`）时回退系统语音输入 Activity，再不可用则提示打字。交互是点击开关：点一下开始、再点结束并识别、说满 20 秒先提示再收尾。识别文本进 §3 的规则解析，产物只预填记账页。**不叠加 AI 二次抽账，也不留开关**——语音从此只有端侧规则一条路，规则读不懂的表达只能去小莉对话页。备注取 `parsed.note`（已剥掉金额与「花了 / 买了 / 大约 / 左右」），`heard` 原文只留给失败提示与「再听一次」。

**截图**：`MlKitTextReader` 端侧 OCR → `ScreenshotRules` 抽金额 / 商户 / 日期 / 分类建议 → 草稿页字段全部可改，低置信行标红并摆候选，未处理完保存键锁定 → 「保存到账单」默认不勾选。批量入口在首页（`＋` 左滑，一次最多 9 张，逐张本机识别后汇成待确认列表），系统分享入口在 `MainActivity` 深链。同样**不发原图给模型**；用户在小莉对话里主动发图时才出设备。

**柱条实现**：RemoteViews 没有画布，每格预置 2 / 6 / 11 / 17dp 四档 `FrameLayout`，按 `ceil(当日 ÷ 最高 × 3)` 只显示一档，不做逐 dp 精确。

**失败与陈旧态**：每次取数成功把数字写进一份可序列化快照（七枚新组件的 `InsightWidgets.Snapshot`，近七日走 `SharedPreferences("widget_state")`）。取数失败时上次成功过就用缓存并挂「· 未更新」，一次都没成功过才显示「—」与「数据没读到，点开 App 看」，柱条整组隐掉——**不拿 ¥0.00 冒充**；每月起始日读不到算整轮失败。

**口径同源**：概览走 `billRepository.observeMonth(默认账本, Period.monthRange(now, startDay)).summary`，与首页那四段是同一条聚合，不在组件里另算一套。结余为负时数字取支出红。

**四条刷新来源**：① 组件 `onUpdate`（`goAsync()` 里跑协程，七枚共用一个 `refreshAll`）；② `MainActivity.onResume`；③ `MainActivity.onStop`——账是在 App 里记的，只靠 `onResume` 会让改动等下一次进 App 才生效，`onStop` 刷完回桌面立刻是新数；④ 每日那次 `AutomationWorker`。四处都调 `TallyWidgets` / `InsightWidgets`，**桌面上没有实例时连库都不碰**（先 `getAppWidgetIds` 判空再决定是否聚合，七枚全没摆时连协程都不起）。八份描述符统一 `updatePeriodMillis = 1800000`（30 分钟）——系统轮询被 ROM 省电策略管着，只当兜底。

**组件只读**：不写库、不弹输入，只把人送到 App 里对应的页面。点击一律落回 `MainActivity`（`singleTask`），带的是通知那两串 `EXTRA_LINK_KEY / EXTRA_LINK_ARG`，与点通知共用同一条 `pendingLink` 通路；`PendingIntent` 的 requestCode 按槽位固定，刷新时 `FLAG_UPDATE_CURRENT` 覆盖同一条而不是攒一堆。快速记账那几格带的是「进记账页并预填分类」，写入仍发生在 App 内那张唯一表单上。

**颜色另起一套**：`RemoteViews` 读不到 Compose 的 `TallyColors`，故 `values/colors.xml` 与 `values-night/colors.xml` 各写一份 `widget_*`。深色卡片 `#1A2320`、亮色 `#FFFDF8`，与 App 的墨纸 / 纸面同色。

**两道已知限制**（真机走查得出，不修）：① MIUI 的组件选择器只认静态 `previewImage`，所以八份描述符全部走 `previewImage`（`res/drawable-nodpi/widget_preview_*.png`），不再用 `previewLayout`——连老的那一枚 `widget_seven_day.xml` 也从 `previewLayout` 换成了 `previewImage`；② 模拟器启动器钉不上组件（`requestPinAppWidget` 与部分直添路径都落空），组件相关的走查一律用真机。

## 25. 导航与界面框架

- 单 NavHost，路由常量集中在 `ui/navigation/TallyNavigation.kt`；首页是唯一常驻页，**无底部导航**。
- `TallyShell` 提供顶栏、抽屉、`＋` 三臂 FAB 与贴底气泡宿主；调试模式下每页挂可拖动控制台浮层。
- 页面状态由 ViewModel 的 `StateFlow` 暴露；一次性事件用 `notice` / `error` 字段 + `dismissMessages()` 消费。
- 抽屉两组：管理（账本 / 分类 / 报销 / 周期 / 分期 / 预算）与系统（设置 · 关于）；二级页返回回到抽屉；选择态返回优先取消勾选。
- 设置 → 数据一段：导入账单 / 导出账单 / 备份与同步 / 回收站 / **导出诊断包**；设置另有「关键词规则」「回收站」两条、「提醒」段（提醒与通知一页）与「使用指南」页。
- 设置 → 关于一段自上而下：版本（`appVersion(context)` 从 APK 读 `versionName (versionCode)`，不硬编码；这一行也是后门，1.2 秒内连点 5 次切调试模式，未开调试时就是一行普通信息）、**项目主页**（`PROJECT_HOME = https://tally.guohang.asia`，`openProjectHome()` 用 `ACTION_VIEW` 打开；打不开浏览器只出一条气泡，不添第二套 UI）、使用指南、许可与依赖、隐私说明。

## 27. 异常与降级总表

| 场景 | 行为 |
|---|---|
| AI 不可用 / 失败 | 记账链路静默回退端侧规则；对话页保留失败消息 + 重试；连续失败进 DISCONNECTED 但不阻断记账 |
| 语音引擎不可用 | 回退系统语音输入 → 再不可用提示打字 |
| OCR 读不出 | 字段留空并提示手填，不猜 |
| 导入对账不平 | 整批回滚，报告留档 |
| 备份口令错 / 哈希不符 / 包版本更高 | 不动现有数据，明确拒绝并提示 |
| 磁盘写入失败 | 导出与备份给明确失败原因，不产生半成品文件 |
| 库 identity hash 对不上（改了实体但设备上还是旧库） | 打开即抛 `IllegalStateException: Room cannot verify the data integrity`，停在可恢复提示，**不清库**；提示里给出「用 `.tally` 备份恢复」的路径 |
| 通知权限被拒 | 通知设置页内联提示 + 去系统设置入口；四类一条不发也不写游标，授权后当天能补 |
| 日志目录建不出来 / 文件写不进 | `DebugLog.attach` 与每次落盘都 `runCatching` 吞掉并继续走内存环，不影响记账；诊断包的 `[trace]` 段如实写「文件日志为空或还没接上目录」 |
| 诊断包写不进下载目录 | 气泡报「诊断包没写出去：⟨原因⟩」，不生成半成品文件、不进系统分享 |
| logcat 读不到（Android 7+ 权限 / 厂商 ROM 返回空） | 诊断包 `[logcat]` 段如实写「读不到——Android 7 之后只能读本 UID，部分厂商 ROM 连自己的也返回空」，并说明这一项缺失不影响上面各段有效 |
| 提醒被 ROM 杀掉 | 进前台补算；文案不承诺准点，只承诺「今天之内」 |
| 组件无位置放不下 / 快捷方式被限流 | 走查记录为厂商行为，添加失败时给一条气泡 |
| 组件取数失败 | 成功过用缓存并标「未更新」；从没成功过显示「—」，不显示 ¥0.00 |
| 长图超高度上限 | 分段生成并提示「内容较长，已分为 2 张」 |
| 图片压缩失败 | 该张不落库，气泡报因 |
| 附件文件已丢失（历史脏值） | 查看器显示「图片文件不存在」占位，不崩；清理任务跳过并计数 |
| 退款超原单 | 拦并显示可退上限，不静默截断 |
| 跨账本迁移遇到期次 | 整批跳过并在弹层与结果各说一句，不静默跳过 |
| 回收站恢复时分类已删 | 引用清成未分类并如实提示「其中 N 笔的原分类已不存在」 |
| 预算保存撞同段同范围 | 不写库，提示「已存在…· ¥x」并附「去看那一条 ›」 |
| 分期计划读不到（已被删除） | 进 `missing` 空态，只有「返回列表」，不出现任何保存类提示 |
| 麦克风权限被永久拒绝 | 直接给「去系统设置」入口，不重复弹框 |

## 28. 日志与诊断包

**落点**：`data/debug/DebugLog.kt`（全项目唯一日志出口）、`data/debug/Diagnostics.kt`（装包）、`data/debug/LogcatTail.kt`（logcat 尾巴）、`data/db/dao/DiagnosticDao.kt`（17 行表计数 + AI 健康度）、`ui/settings/SettingsScreen.kt`（入口）、`di/AppGraph.kt`（排锁探针）。

**为什么只有这一个出口**：日志的隐私边界只能在写日志那一层守。只要 `DebugLog` 的入口不接收账单内容，导出时就不需要猜哪一行带了金额或备注——`log(tag, message)` 的 `message` 由调用方决定，约定里不写账单字段。

### 28.1 日志落盘（`DebugLog`）

| 项 | 规格 |
|---|---|
| 内存环 | 300 行（`RING_LINES`），给页面上那张调试控制台用 |
| 文件日志 | `filesDir/logs/tally.log`，> 512KB（`FILE_CAP_BYTES`）时滚成 `tally.log.1`，只留两份，磁盘上限 1MB |
| 写入线程 | 单线程 `AppLog`（daemon、`MIN_PRIORITY`），`attach()` 之前写的行先攒在 `pending` 里，接上目录一次补落盘 |
| 崩溃留档 | `crash-yyyyMMdd_HHmmss.log`，**同步写**（进程下一秒就没了，排队等于什么都没留下）；写的是线程名、`version`、最深 6 层因果链、每层 24 帧；只留最近 5 份（`CRASH_KEEP`） |
| 版本注入 | `CrashInfo.version` 由 `TallyApplication.onCreate` 注入一次——`DebugLog` 不该依赖 `Context` |
| 异常钩子 | `TallyApplication.onCreate` 最前（第一行日志之前）`attach` + `installCrashRecorder()`：先 `recordCrash`，再把异常交回系统原来的处理器，不改变崩溃行为、不吞异常 |

### 28.2 诊断包（`Diagnostics.export`）

入口是设置 → 数据 →「导出诊断包」，`exporting` 期间不重入；成功气泡报文件名并立刻 `Intent.createChooser(ACTION_SEND)` 顶起系统分享，失败就地报「诊断包没写出去：⟨原因⟩」。文件名 `tally_diagnostics_yyyyMMdd_HHmmss.txt`，写公共下载目录（`PublicDownloads.write`）。

| 段 | 内容 |
|---|---|
| 头部 | 生成时间 + 一行内容边界声明 |
| `[app]` | `versionName` / `versionCode` / `buildType` |
| `[db]` | `user_version`、`identity_hash` 前 8 位、`journal_mode`、`db_bytes`、`wal_bytes`、`free_mb` |
| `[dev]` | brand / model / device / android(SDK) / firmware / abis / locale / zone |
| `[set]` | 主题、每月起始日、时间精度、报销／账单图片／小莉／货币符号／千分位／调试模式开关、AI 目标 |
| `[row]` | 17 项行数（见下） |
| `[ai]` | 目标服务商与模型、`last_error`、连续失败次数 |
| `[trace]` | `DebugLog.fileTail()` 最后 400 行（`.1` + 当前文件） |
| `[crash]` | 最近 3 份崩溃留档，每份前 60 行 |
| `[logcat]` | crash buffer + 本进程，各 ≤ 120 行，已过脱敏 |

**行数那 17 项**：`bill`、`bill_live`、`ledger`、`ledger_live`、`category`、`budget`、`attachment`、`import_batch`、`recurring_rule`、`installment_plan`、`ai_config`、`ai_conversation`、`ai_message`、`ai_message_attachment`、`ai_report`、`keyword_rule`、`app_setting`。**行数是唯一带出的"数据量"**——它只说明有多少条，不含任何一条的内容。

**隐私边界（必须守住）**：诊断包**不含**账单金额、备注、分类名、账本名、图片、API Key 与网关地址。所以 `DiagnosticDao.aiHealth()` 只取 `provider / model / last_error / consecutive_failures`，不取 `base_url` 与 `key_reference`（`last_error` 存的是失败类型名而不是响应正文）；`[set]` 里的 `ai_target` 也只有服务商与模型名。`PRAGMA` 与 `room_master_table` 不在 DAO 里查——Room 解析不了 `PRAGMA`，那张表要到运行时才存在，只能走裸连接（`rawFirst`）。

**LogcatTail 的取舍**：白名单，不是黑名单。我们自己的代码从不走 `android.util.Log`（全进 `DebugLog`），所以 logcat 里唯一有价值的是框架与三方库的话。按"本进程全收"实测 300 行里约 150 行是 MIUI 的 `InsetsSource`，其余是 `MIUIInput` / `HWUI` / `BLASTBufferQueue`，把真正那两条 `SQLiteLog` 埋掉了——所以宁可少收：只留 `AndroidRuntime` / `System.err` / `StrictMode` / `SQLiteLog` / `SQLiteDatabase` / `CursorWindow` / `DefaultDatabase` / `WM-*` / `WorkManager*` / `WorkContext` / `coil*` / `OkHttp*` / `EGL*` / `vulkan` / `Adreno*` / `OpenGLRenderer` 与 `guohangbk.tally`，**E 级一律留**（真出问题时级别比 tag 诚实）。行级脱敏先跑：命中 `INSERT ` / `REPLACE INTO` / `UPDATE ⟨表⟩ SET` / `SELECT … FROM` / `/storage/` / `/sdcard` / `content://` / `file://` / 常见图片扩展名的整行直接丢弃，单行截到 240 字符，`logcat` 进程 4 秒超时后 `destroy()`。

### 28.3 排锁探针（`AppGraph`）

Room 不显式配置时会把「查询」和「事务」压在同一个单线程 executor 上，一条长事务会让后面所有读写一起等——光看业务侧取数耗时只能看到「都慢」，看不到是谁持着锁。所以 `AppGraph.fileDatabase` 给两个 executor 各包一层探针：事务单线程、查询固定 4 线程，排队 > 200ms 或执行 > 200ms 写一行 `DebugLog.log("Lock", "⟨事务|查询⟩ 排队⟨x⟩ms 执行⟨y⟩ms")`。这也是全应用唯一可信的读写耗时来源——业务侧那些 Flow 是失效驱动的，一条订阅会发很多次。
